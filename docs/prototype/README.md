# 프로토타입 v0.1 — 설계, 검증 결과, 한계

## 1. MVP 단계별 구현 범위

| 단계 (조사 문서 §7) | 구현 | 검증 방법 | 상태 |
|---|---|---|---|
| 1. 녹화 영상 → 사람/위험물 탐지 | YOLO11n(사람·COCO knife/bat/scissors) + 합성 인식 백엔드 | 실사진·영상에서 사람 4명·관절점 검출, CPU 약 175ms/프레임 | 동작 (실데이터 정확도 미측정) |
| 2. Tracking + 행동 분석 | ByteTrack(실영상) / 합성 추적, 자세 기반 쓰러짐·타격 동작, 속도·접근·도주·추격, 구역 체류 | 특징값 분리도 확인(타격 limb 2.3–3.5 vs 보행 0.8 H/s 등) | 동작 |
| 3. Risk Engine | 증거 누적 + 반대 증거 + 장소·시간 보정 + 정책 단계 + 감쇠 | 사건 단위 평가, 정상-유사 상황 | 동작 (가설 정책) |
| 4. 웹 관제 Dashboard | 알림 큐, 실시간 영상, 사건 상세, 판단 근거, KPI, 평가 | Playwright로 화면 흐름·모바일 폭 점검 | 동작 |
| 5. 사건 영상 확보 + 요약 + 신고 지원 | 사건 전 8초 버퍼 포함 H.264 클립, 템플릿 요약(근거 추적 가능), 신고 패키지·문안, 확정·기록 절차 | API 테스트(확인 체크 없으면 확정 불가, 확정 전 신고 기록 불가) | 동작 |
| 6. 실제 IP CCTV 연동 | RTSP(TCP) 입력, 서브샘플링, 자동 재연결 | MediaMTX RTSP 서버로 IP 카메라를 대신해 YOLO 분석까지 확인, 재연결 백오프 확인 | 동작 (실제 카메라 미검증) |
| 7. Multi-Camera | 카메라 토폴로지 기반 이동 예상 + 출현 시간창 + 의상 색상 유사도로 **동일인 후보**(관제자 확인 필요) | 흉기→추격이 cam01→cam02→cam03에 걸친 하나의 사건으로 묶이고, 유사도 0.95 이상으로 연결됨 | 동작 (합성 환경) |

## 2. 실행 흐름 (`knife_threat_chase` 예)

1. cam01에서 칼을 든 인물 #1이 #2에게 접근 → `WEAPON_THREAT` 관문 증거(흉기 보유 × 근접) + 접근 → ATTENTION
2. 거리 1.3H, 근접 접촉 → HIGH_RISK, #2 급가속 이탈(도주 추정) → EMERGENCY, 관제자 알림
3. #1이 달아나는 #2를 뒤따라 달림 + 추격 전 갈등 정황(접근, 흉기 근접) → `CHASE` EMERGENCY
4. 두 사람이 화면 오른쪽으로 이탈 → 인접 cam02 "이동 예상", cam02 진입 인물이 색상 유사도로 동일인 후보 연결 → 같은 사건에 cam02 추가
5. 사건 종료 후 카메라별 클립(사건 전 버퍼 포함), 요약, 신고 패키지(권장 기관 112, 신고 문안) 생성
6. 관제자: 열람 → 확인(ACK) → 신고 지원 탭에서 수정 → "영상으로 직접 확인" 체크 → 확정 → 직접 신고 후 기록 → KPI 반영

## 3. Risk Engine 요약

```
raw   = gate × (base + (1 − base) × noisy_OR(w_k × e_k)) × (1 − max 반대증거)
score = calibrate( 1 − (1 − raw)^(장소계수 × 야간계수) )
level = policy.levels 임계값 (유형별 상한: 배회 ≤ WARNING, 주변 사람 없는 흉기 보유 ≤ ATTENTION)
표시 점수 = max(현재, 이전 × 0.5^(Δt / 반감기))   # 깜빡임 방지
```

| 상황 | 관문(필수) | 보강 증거 | 반대 증거 |
|---|---|---|---|
| 폭행/싸움 | 2초 중 타격 동작 비율(팔 속도·상대 방향 팔 뻗음 변동·낮은 몸 이동속도·근접) | 누적 시간, 상대 쓰러짐, 이탈(도주), 위험물 | – |
| 흉기·위험물 위협 | 위험물 보유(2초 평균 신뢰도) × 근접 | 접근(거리 감소 동반), 상대 급가속 이탈, 접촉(떨어져 있다 가까워진 경우만), 공격 동작, 추격 | 갈등 없이 함께 이동하는 일행 |
| 추격 | 달리는 상대를 향해 같이 달리는 시간 비율 | 추격 전 갈등(접근·폭행·흉기 근접), 상대의 갑작스러운 도주 시작, 위험물, 거리 좁혀짐 | 함께 달리는 일행(갈등 정황 없을 때) |
| 쓰러짐 | 누운 자세 지속(몸통 각도, 화면 가장자리에 잘린 몸은 판정 안 함) | 급격한 쓰러짐, 장시간, 움직임 없음, 폭행 직후 | – |
| 침입 | 출입통제구역 체류(운영 시간대) | 장시간 체류 | – |
| 비정상 배회 | 감시구역 체류 시간 | 이동거리/순변위 비, 방향 전환 횟수 | – |

모든 수치는 `configs/policy.default.yaml`에 있으며 `provenance: hypothesis`로 표시됩니다.
운영 기준은 `safewatch eval --fit-policy`가 **PR 곡선에서 `fit_targets`(정책 입력: 예 WARNING 재현율 ≥ 0.85, HIGH_RISK 정밀도 ≥ 0.90)를 만족하는 운영점**으로 다시 계산합니다.

## 4. 검증 결과 (합성 데이터, 2026-10-01)

11개 시나리오 × seed 3 = 33회, GT 21건, 카메라-시간 0.46h.
전체 리포트: [기본 노이즈](eval-default/report.md) · [강한 노이즈](eval-hard/report.md)

| 운영점 | 기본 노이즈: P / R / FP | 강한 노이즈: P / R / FP |
|---|---|---|
| ATTENTION (θ 0.30) | 0.71 / 1.00 / 11 | 0.63 / 1.00 / 15 |
| **WARNING (θ 0.50, 팝업 기준)** | **1.00 / 1.00 / 0** | **1.00 / 1.00 / 0** |
| HIGH_RISK (θ 0.70) | 1.00 / 0.86 / 0 | 1.00 / 0.76 / 0 |
| EMERGENCY (θ 0.85) | 1.00 / 0.71 / 0 | 1.00 / 0.57 / 0 |

- 유형별 평균 탐지 지연(WARNING 도달): 폭행 2.6s, 흉기 위협 2.1~3.4s, 추격 1.7s, 쓰러짐 2.1s, 침입 3.0s, 배회 70s(정의상 체류 시간 필요).
- 정상-유사 상황 최고 점수(강한 노이즈): 칼 들고 단독 보행 0.48, 휴대폰 사용자 0.43, 배트 든 일행 0.31, 조깅 0.29 → 모두 팝업 기준 미만이지만 **여유가 줄어듦**.
- `--fit-policy` 결과 {ATTENTION 0.56, WARNING 0.82, HIGH_RISK 0.83, EMERGENCY 0.84}: 합성 데이터가 너무 잘 분리되어 임계값이 한쪽으로 몰림. **기능 동작 확인용이며 운영값으로 쓰면 안 됨**.
- 실영상 점검에서 오탐 1건 발견·수정: 상반신만 보이는(화면 아래가 잘린) 인물을 "누운 자세"로 판정 → 가장자리에 잘린 몸과 다리가 보이지 않는 경우는 자세를 판정하지 않도록 변경.

### 평가 해석 시 주의
1. **합성 데이터 결과이며 실제 CCTV 성능이 아닙니다.** 시나리오는 특징 설계 과정에서도 사용되었으므로(개발 데이터 = 평가 데이터) 일반화 근거가 아닙니다.
2. 인식 오류(미검출, 흉기 검출률 55%, 휴대폰→칼 오인 8% 등)는 `NoiseModel` **가정값**입니다. Phase 1에서 실제 모델의 오류율로 교체해야 합니다.
3. FP/카메라·시간은 카메라-시간이 0.46h뿐이라 참고용입니다. 실제 장시간 정상 영상으로 측정해야 합니다.

| 보안/권한 | 인증 없음(로컬 프로토타입) | 관제자 로그인, 역할 권한, 감사 로그 보존 정책, 영상 보관기간 |
